# 混合模式启动指南

> 数据库用 Docker 容器运行，后端用本地 Python 运行。改代码立即生效，不用装任何数据库。

---

## 前提条件

- [x] 已安装 Python 3.10
- [x] 已安装 Node.js 16+
- [x] 已安装 Docker Desktop（并启动它）

确认 Docker Desktop 正在运行：任务栏右下角能看到 Docker 图标，图标不显示红色/黄色就说明已启动。

---

## Docker 快速入门（5 分钟）

你只需要知道这几个命令就够用了：

```bash
# 启动指定服务（后台运行，-d 表示 detach 脱离终端）
docker-compose up -d neo4j mysql redis milvus kb_postgres

# 查看哪些容器在运行
docker-compose ps

# 查看某个服务的日志（实时滚动，Ctrl+C 退出）
docker-compose logs -f neo4j

# 停止所有服务
docker-compose down

# 停止并删除所有数据（慎用，数据会丢失）
docker-compose down -v
```

**关键概念**：
- `docker-compose up -d` = 根据 `docker-compose.yml` 的配置，下载镜像（首次）并启动容器
- 容器 = 一个隔离的迷你虚拟机，里面只跑一个服务（比如 MySQL）
- 端口映射 `"13306:3306"` = 容器内部的 3306 端口映射到你电脑的 13306 端口，所以你访问 `localhost:13306` 就能连上容器里的 MySQL
- Volume = Docker 管理的数据持久化目录，容器删了数据还在（除非 `down -v`）

## 第 1 步：创建 .env 配置文件

在项目根目录 `D:\GustoBot\` 下创建 `.env` 文件：

```bash
copy .env.example .env
```

然后编辑 `.env`，修改以下配置（其他保持默认即可）：

```ini
# ===================== 必填：LLM 配置 =====================
# 你必须有 LLM API 的账号，否则后端启动后无法正常对话
LLM_PROVIDER=openai
LLM_MODEL=qwen3-max
LLM_API_KEY=sk-你的实际API密钥
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1

# Embedding 配置（知识库检索依赖）
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=text-embedding-3-small
EMBEDDING_API_KEY=sk-你的实际API密钥
EMBEDDING_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
EMBEDDING_DIMENSION=1536

# ===================== 数据库端口（必须和 Docker 映射一致）=====================
# 注意：docker-compose.yml 里 MySQL 映射到宿主机 13306，不是 3306
DATABASE_URL=mysql+pymysql://recipe_user:recipepass@localhost:13306/recipe_db

# Neo4j：docker-compose.yml 映射到宿主机 17687
NEO4J_URI=bolt://localhost:17687
NEO4J_USER=neo4j
NEO4J_PASSWORD=recipepass

# Redis：端口一致，不用改
REDIS_URL=redis://localhost:6379

# Milvus：端口一致，不用改
MILVUS_HOST=localhost
MILVUS_PORT=19530

# PostgreSQL（知识库）：docker-compose.yml 映射到宿主机 5433
KB_PG_PORT=5433

# ===================== 其他保持默认即可 =====================
DEBUG=True
APP_NAME=GustoBot
APP_VERSION=0.1.1
API_V1_PREFIX=/api/v1
HOST=0.0.0.0
PORT=8000
```

## 第 2 步：启动数据库容器

打开终端，进入项目根目录：

```bash
cd D:\GustoBot
```

启动数据库和中间件（不启动后端和前端）：

```bash
docker-compose up -d neo4j mysql redis etcd minio milvus kb_postgres kb_ingest
```

> **这条命令做了什么**：
> - `up` = 创建并启动容器
> - `-d` = 后台运行（detached），终端不会被占用
> - 最后一串是服务名，对应 `docker-compose.yml` 里定义的各个服务
> - 首次运行会下载镜像，可能需要几分钟（取决于网速）
> - 镜像下载后会缓存，下次启动秒开

等待容器启动完成（约 30 秒），然后检查状态：

```bash
docker-compose ps
```

正常情况下你会看到类似这样的输出：

```
NAME                STATUS          PORTS
gustobot-neo4j      Up X minutes    0.0.0.0:17474->7474/tcp, 0.0.0.0:17687->7687/tcp
gustobot-mysql      Up X minutes    0.0.0.0:13306->3306/tcp
gustobot-redis      Up X minutes    0.0.0.0:6379->6379/tcp
gustobot-milvus     Up X minutes    0.0.0.0:19530->19530/tcp
gustobot-kb_postgres Up X minutes   0.0.0.0:5433->5432/tcp
...
```

> **怎么看**：STATUS 显示 `Up` 就是正常，显示 `Exit` 或 `Restarting` 就是有问题。
> 用 `docker-compose logs <服务名>` 看报错信息。

## 第 3 步：安装 Python 依赖（首次）

```bash
# 创建虚拟环境
python -m venv venv

# 激活虚拟环境
venv\Scripts\activate

# 安装依赖
pip install -r requirements.txt
```

> **虚拟环境做了什么**：创建一个独立的 Python 环境，`pip install` 的包只装在这个目录里（`venv/`），不会污染系统 Python。每次开新终端都要先 `venv\Scripts\activate` 激活。

## 第 4 步：启动后端

```bash
python run.py start
```

看到以下输出说明启动成功：

```
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
INFO:     Started reloader process
INFO:     Started server process
INFO:     Waiting for application startup.
Starting GustoBot v0.1.1
Database tables ready
```

> **热重载**：`DEBUG=True` 时 Uvicorn 会监听文件变化，你修改 Python 代码保存后，服务自动重启，不用手动操作。

验证后端正常：

```bash
# 另开一个终端
curl http://localhost:8000/health
```

应返回 `{"status": "healthy", ...}`。

## 第 5 步：启动前端（可选）

另开一个终端：

```bash
cd D:\GustoBot\web
npm install
npm run dev
```

浏览器打开 `http://localhost:5173`，即可看到聊天界面。

## 日常开发流程

每天开发时只需两步：

```bash
# 终端 1：启动数据库（如果之前没关就不用再启动）
docker-compose up -d neo4j mysql redis etcd minio milvus kb_postgres kb_ingest

# 终端 1：启动后端
venv\Scripts\activate
python run.py start

# 终端 2：启动前端（可选）
cd web && npm run dev
```

改代码 → 保存 → 后端自动重载 → 刷新浏览器测试。

## 常用 Docker 命令速查

```bash
# 查看所有容器状态
docker-compose ps

# 查看某个服务的实时日志
docker-compose logs -f backend
docker-compose logs -f neo4j

# 重启某个服务
docker-compose restart neo4j

# 停止所有服务（保留数据）
docker-compose down

# 停止并删除所有数据（下次启动会重新初始化）
docker-compose down -v

# 查看磁盘占用
docker system df

# 清理无用镜像/容器/网络（释放磁盘空间）
docker system prune
```

## 常见问题

### 1. `docker-compose up` 报错 "port is already allocated"

说明端口被占用了。检查是哪个进程占的：

```bash
# Windows
netstat -ano | findstr :6379
```

找到 PID 后 `taskkill /PID <pid> /F` 杀掉，或者改 `.env` 用其他端口。

### 2. 后端启动报 "Connection refused"

数据库容器还没完全就绪。等 30 秒再试，或者检查容器状态：

```bash
docker-compose ps
docker-compose logs mysql
```

### 3. 后端报 "Unknown database 'recipe_db'"

MySQL 首次启动需要一点时间初始化。等 1 分钟再重启后端：

```bash
docker-compose restart mysql
# 等 30 秒
python run.py start
```

### 4. Docker Desktop 启动失败

- 确认 Windows 开启了虚拟化（任务管理器 → 性能 → CPU → 虚拟化：已启用）
- 确认开启了 WSL 2（Docker Desktop Settings → General → Use the WSL 2 based engine）
- 如果还是不行，重启电脑试试

### 5. 下载镜像很慢

配置 Docker 镜像加速器（Docker Desktop → Settings → Docker Engine）：

```json
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://registry.docker-cn.com"
  ]
}
```
