> **目标**：能从「用户发一句话」讲到「后端返回答案」，中间经过了哪些函数、哪些模块。

```
前端 POST /api/v1/chat/
```

## 3. 请求模型：ChatRequest (`chat.py:28-39`)

```python
class ChatRequest(BaseModel):
    message: str = Field(..., description="User message", min_length=1, max_length=5000)
    session_id: Optional[str] = Field(None, description="Session ID for conversation continuity")
```

**字段说明**：

| 字段 | 必填 | 默认值 | 用途 |
|------|------|--------|------|
| `message` | 是 | - | 用户输入的文本，1~5000 字符 |
| `session_id` | 否 | `None` | 传入已有会话 ID 则复用，不传则新建 |

## 4. 数据库会话注入：get_db (`database.py:51-59`)

```python
def get_db() -> Generator[Session, None, None]:
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

这是一个 FastAPI 依赖函数。通过 `Depends(get_db)` 注入到路由函数中，每个请求获得一个独立的 SQLAlchemy Session，请求结束后自动关闭。

## 5. 会话管理：get_or_create_session (`chat.py:63-78`)

```python
def get_or_create_session(db: Session, session_id: Optional[str], user_id: str) -> str:
    if session_id:
        session = chat_session.get(db, id=session_id)
        if session:
            return session_id

    new_session_id = str(uuid.uuid4())
    session_data = ChatSessionCreate(
        id=new_session_id,
        user_id=user_id,
        title=f"Chat {datetime.now().strftime('%Y-%m-%d %H:%M')}"
    )
    chat_session.create(db, obj_in=session_data)
    return new_session_id
```

**逻辑**：

1. 如果前端传了 `session_id`，调用 `chat_session.get()`（`CRUDBase.get`，`base.py:29`）查数据库
2. 找到则返回该 `session_id`，继续使用旧会话
3. 没找到（或未传），生成新的 UUID，调用 `chat_session.create()`（`base.py:39`）写入 `chat_sessions` 表
4. 标题自动生成为 `"Chat 2026-06-20 14:30"` 这样的格式

**ORM 模型** (`db/models/chat_session.py:13-81`)：

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | String(255), PK | UUID 字符串主键 |
| `user_id` | String(255) | 用户标识，无外键关联，轻量级设计 |
| `title` | String(500) | 会话标题 |
| `created_at` | DateTime | 创建时间，数据库自动生成 |
| `updated_at` | DateTime | 更新时间 |
| `is_active` | Boolean | 软删除标记，默认 `True` |

## 6. 消息持久化：save_message (`chat.py:81-112`)

```python
async def save_message(db: Session, session_id: str, message: str, is_user: bool,
                       route: Optional[str] = None, metadata: Optional[Dict] = None):
```

**流程**：

1. **获取序号**：调用 `chat_message.get_latest_by_session()`（`crud_chat_message.py:50`）查最后一条消息的 `order_index`，加 1 得到新序号
2. **构造元数据**：将 `route` 写入 `message_metadata` 字典；如果传入了 `metadata`，过滤掉 `agent_state` 键（避免存入整个图状态）
3. **创建记录**：构造 `ChatMessageCreate` Pydantic 对象，调用 `chat_message.create()`（`base.py:39`）写入 `chat_messages` 表
4. **更新会话时间**：调用 `chat_session.update_activity()`（`crud_chat_session.py:100`）刷新 `updated_at`

**ORM 模型** (`db/models/chat_message.py:11-76`)：

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | Integer, PK | 自增主键 |
| `session_id` | String(255), FK | 外键关联 `chat_sessions.id`，级联删除 |
| `message_type` | String(50) | `"user_query"` 或 `"agent_response"` |
| `content` | Text | 消息正文 |
| `message_metadata` | JSON | 路由信息、来源等附加数据 |
| `order_index` | Integer | 消息在会话中的顺序 |
| `created_at` | DateTime | 创建时间 |

在 `chat` 端点中，`save_message` 被调用两次：
- 第 261 行：`await save_message(db, session_id, request.message, is_user=True)` -- 保存用户消息
- 第 279 行：`await save_message(db, session_id, result["message"], is_user=False, route=..., metadata=...)` -- 保存助手回复

### 7.2 图执行：graph.ainvoke (`chat.py:138`)

```python
result = await graph.ainvoke(input_state, config=config)
```

`graph` 是在 `lg_builder.py:973` 编译的 LangGraph `StateGraph`：

```python
checkpointer = MemorySaver()
builder = StateGraph(AgentState, input=InputState)
builder.add_node(analyze_and_route_query)
builder.add_node(respond_to_general_query)
builder.add_node(get_additional_info)
builder.add_node("create_research_plan", create_research_plan)
builder.add_node(create_image_query)
builder.add_node(create_file_query)
builder.add_node(create_kb_query)

builder.add_edge(START, "analyze_and_route_query")
builder.add_conditional_edges("analyze_and_route_query", route_query)

graph = builder.compile(checkpointer=checkpointer)
```

**图结构**：

```
START
  |
  v
analyze_and_route_query()   -- 意图识别节点
  |
  v
route_query()               -- 条件路由函数（不是节点，是条件边）
  |
  +---> respond_to_general_query()   general-query
  +---> get_additional_info()        additional-query
  +---> create_research_plan()       graphrag-query / text2sql-query
  +---> create_image_query()         image-query
  +---> create_file_query()          file-query
  +---> create_kb_query()            kb-query
  |
  v
END
```

### 7.3 状态模型 (`lg_states.py`)

**InputState**（第 50 行）-- 图的输入：

```python
@dataclass(kw_only=True)
class InputState:
    messages: Annotated[list[AnyMessage], add_messages]
```

**AgentState**（第 92 行）-- 图的完整状态，继承 InputState：

```python
@dataclass(kw_only=True)
class AgentState(InputState):
    router: Router          # 路由分类结果
    steps: list[str]        # 研究步骤
    documents: list[str]    # 检索到的文档
    question: str           # 问题文本
    answer: str             # 回答文本
    hallucination: GradeHallucinations  # 幻觉检查结果
    sources: list           # 知识来源
```

**Router**（第 8 行）-- 路由分类模型：

```python
class Router(BaseModel):
    logic: str = ""
    type: Literal[
        "general-query",      # 日常对话
        "additional-query",   # 需要更多信息
        "kb-query",           # 知识库查询
        "graphrag-query",     # 图谱查询
        "image-query",        # 图片处理
        "file-query",         # 文件处理
        "text2sql-query",     # 统计查询
    ] = "kb-query"
    question: str = ""
    decision: Optional[str] = None
    confidence: Optional[float] = None
    reasoning: Optional[str] = None
```

### 7.4 意图识别：analyze_and_route_query (`lg_builder.py:103-194`)

这是图的第一个节点。流程：

1. 创建 `ChatOpenAI` 实例（第 122 行）
2. 拼接系统提示 `ROUTER_SYSTEM_PROMPT` + 历史消息（第 131 行）
3. 调用 `model.with_structured_output(Router).ainvoke(messages)`（第 156 行），让 LLM 返回结构化的 `Router` 对象
4. 校验返回的 `type` 是否在允许列表中（第 145-153 行定义了 7 种类型）
5. 如果 LLM 失败或返回无效类型，回退到 `_heuristic_router()`（第 986 行）进行关键词匹配

**关键词回退逻辑**（`_heuristic_router`，第 986-1022 行）：
- 包含「统计」「多少」「总数」「排名」等 -> `text2sql-query`
- 包含「怎么做」「做法」「食材」「配料」等 -> `graphrag-query`
- 其他情况返回 `None`，最终默认 `kb-query`

### 7.5 条件路由：route_query (`lg_builder.py:197-236`)

```python
def route_query(state: AgentState) -> Literal[...]:
```

这不是图节点，而是 `add_conditional_edges` 使用的路由函数。它根据 `state.router.type` 返回下一个节点名：

| router.type | 返回的节点名 |
|-------------|-------------|
| `general-query` | `respond_to_general_query` |
| `additional-query` | `get_additional_info` |
| `graphrag-query` / `text2sql-query` | `create_research_plan` |
| `image-query` | `create_image_query` |
| `file-query` | `create_file_query` |
| `kb-query` | `create_kb_query` |

另外，如果 `config` 中包含 `image_path` 或 `file_path`，会优先路由到对应处理节点（第 214-220 行）。

### 7.6 六条处理路线概要

| 节点函数 | 行号 | 功能 |
|---------|------|------|
| `respond_to_general_query` | 239 | 纯 LLM 对话，不调用外部服务 |
| `get_additional_info` | 268 | 先过 Guardrails 判断是否在服务范围内，再生成追问回复 |
| `create_research_plan` | 804 | 调用 Neo4j 图数据库 + 多工具工作流（Cypher/GraphRAG/Text2SQL） |
| `create_image_query` | 478 | 图片识别（视觉模型）或图片生成（CogView-4 API） |
| `create_file_query` | 622 | 文件上传处理，支持 txt/md/csv/json/xlsx |
| `create_kb_query` | 711 | 向量知识库检索，先尝试 multi-tool 工作流，失败后回退到直接检索 |

每个节点都返回 `{"messages": [AIMessage(content=...)]}` 格式，LangGraph 会将其追加到状态的 `messages` 列表中。

## 11. 流式输出的实现方式

### 11.1 流式端点 (`chat.py:316-353`)

```python
@router.post("/stream")
async def chat_stream(request: ChatRequest, db: Session = Depends(get_db)) -> StreamingResponse:
```

路径：`POST /api/v1/chat/stream`

核心返回：

```python
return StreamingResponse(
    stream_agent_response(...),
    media_type="text/event-stream",
    headers={
        "Cache-Control": "no-cache",
        "Connection": "keep-alive",
        "X-Accel-Buffering": "no"   # 禁用 nginx 缓冲
    }
)
```

### 11.2 流式生成器：stream_agent_response (`chat.py:185-241`)

这是一个 `AsyncGenerator`，按 SSE（Server-Sent Events）格式逐块输出：

1. **发送元数据**（第 191 行）：`type="metadata"`，告知前端开始处理
2. **调用 process_agent_query**（第 200 行）：实际处理仍然是一次性完成的
3. **发送路由信息**（第 203 行）：`type="metadata"`，包含 route 和 logic
4. **逐词发送回答**（第 216 行）：将回答文本按空格拆分，每个词作为独立 chunk 发送，每块间隔 50ms 模拟流式效果
5. **发送完成信号**（第 227 行）：`type="done"`，附带 sources

**数据格式**（ChatStreamChunk，第 54 行）：

```python
class ChatStreamChunk(BaseModel):
    type: str           # 'message', 'metadata', 'error', 'done'
    content: Optional[str] = None
    metadata: Optional[Dict[str, Any]] = None
    session_id: Optional[str] = None
    route: Optional[str] = None
```

每块输出格式为：`data: {"type": "message", "content": "红烧肉 ", ...}\n\n`

**注意**：当前实现是「伪流式」——Agent 仍然一次性处理完毕，只是在输出阶段逐词发送。真正的流式需要在 LLM 调用层使用 `astream()` 逐 token 输出。

## 12. 异常处理

### 12.1 全局异常处理器 (`main.py:120-129`)

```python
@application.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception) -> JSONResponse:
    logger.error("Unhandled exception on {} {}: {}", request.method, request.url, exc)
    return JSONResponse(
        status_code=500,
        content={
            "error": "Internal Server Error",
            "message": str(exc) if settings.DEBUG else "An unexpected error occurred",
        },
    )
```

捕获所有未处理的异常，返回 500 错误。`DEBUG` 模式下会暴露异常详情，生产环境只返回通用提示。

### 12.2 Agent 层异常 (`chat.py:174-182`)

```python
except Exception as e:
    logger.error(f"Agent query failed: {e}", exc_info=True)
    return {
        "message": "抱歉，处理您的请求时出现了错误。请稍后重试。",
        "route": "error",
        "route_logic": f"Error: {str(e)}",
        "sources": [],
        "metadata": {"error": str(e)}
    }
```

`process_agent_query` 内部捕获所有异常，返回一个带有 `route="error"` 的降级响应，而不是让异常向上抛出。这意味着即使 Agent 内部崩溃，用户仍然能收到一条友好的错误消息。

### 12.3 消息保存层异常 (`chat.py:110-112`)

```python
except Exception as e:
    logger.error(f"Failed to save message: {e}")
    return None
```

消息保存失败不会阻断主流程，只是返回 `None`，端点仍会正常返回响应。

### 12.4 流式异常 (`chat.py:234-241`)

```python
except Exception as e:
    error_chunk = ChatStreamChunk(type="error", content=f"处理请求时出错: {str(e)}", ...)
    yield f"data: {error_chunk.model_dump_json()}\n\n"
```

流式模式下，异常通过 SSE 的 `type="error"` 块告知前端。
